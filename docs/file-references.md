# 文件引用、原生附件与展示地址

**当前实现。** 本文维护模块自身的引用和版本语义。
前后端应共用模块自己的映射实现，不让 Cockpit 本体了解文件路径规则。

## 1. 两类文件引用，不混成一个协议

| 来源 | 原生消息中已有的内容 | 前端如何寻址 |
| --- | --- | --- |
| 用户上传的附件 | 指向已保存托管文件的原生 attachments[].path | 托管 path 转文件 URL |
| 助手回复中的文件 | 标准 Markdown 文件 link/image | 原生消息身份和完整引用目标转展示 URL |

fileId 定位托管文件；消息 ID 定位原生消息。
文件模块不重新发明消息身份，也不修改 Copilot 保存的正文。

## 2. 用户上传：规范 path 与 URL 的互逆映射

模块共享两个函数，名称示意：

```ts
toNativePath(fileUrl, nativePathPrefix, apiBase)
toFileUrl(nativePath, nativePathPrefix, apiBase)
```

对于同一个模块管理的规范文件：

```text
// 使用同一 nativePathPrefix 和 apiBase
toFileUrl(toNativePath(url, prefix, base), prefix, base) = url
toNativePath(toFileUrl(path, prefix, base), prefix, base) = path
```

这些关系只适用于受支持的托管地址，不适用于任意操作系统路径或远程 URL。
映射依据部署时确定的托管根和 URL 前缀，不能在浏览器猜测服务器用户 HOME。
保留文件类型所需后缀与原始显示名是不同事情；显示名不作为磁盘路径权威。

上传响应可以直接返回两种表示，减少前端推断：

```text
fileId
url
attachment: { type: "file", path, displayName }
```

前端可直接把 attachment 加入草稿；如果只取得 URL，则通过同一共享映射获得 path。
收到原生用户消息后，反向映射附件 path，就能找到同一份文件。
已经由 fileId 定位的用户附件不需要再拼 session/message。
规范 URL 为 `<apiBase>/files/<fileId>/<bodyName>`，
对应 `<nativePathPrefix><fileId>/ready/<bodyName>`。
URL 保留受控的 body 文件名/后缀，例如 body.png，不依赖查询元数据才能反向映射。
显示文件名仍是独立元数据，不把用户文件名直接当存储路径。

规范地址不包括下载参数、预览参数或任意来源前缀。
解码、路径分隔符和文件身份必须有唯一规则；非法或非托管输入明确拒绝。
编码不是认证，下载仍遵循宿主访问保护。

## 3. 助手回复：普通 Markdown，不要求发布工具

Agent 可以正常回复：

```markdown
[下载报告](./report.csv)

![效果图](./abc.png)
```

The module's default instructions ([`src/instructions.md`](../src/instructions.md), packaged as
`dist/instructions.md`) tell agents to use this form in the reply body; paths only in code, plain text
or tool output are not captured.

模块后端收到 delta 时即可对当前消息已识别的本地引用进行 best-effort 捕获，
不等待整条回复完成；同一条新实时消息的完整事件可补全遗漏的引用。
历史读取和恢复时重放的旧消息不走捕获路径。
前端按同一规则生成展示地址：

```text
replyFileUrl(原生消息上下文, "./abc.png")
```

消息上下文必须来自后端/原生事实，不是数组下标、React key 或前端随机 ID。
主 Agent 与子 Agent 使用一致的原生身份接口；不能把嵌套 UI 的组合 session key
误认为真正 session ID。

当前编码是 UTF-8 JSON 数组的 Base64URL：

```text
[nativeSessionId, stableBackendMessageId, "./abc.png"]
```

助手使用原生 data.messageId，session 为真实的根 session；
agentId 只作展示信息，不参与 URL 编码。不要使用前端嵌套显示 key 或数组下标。
同一条消息的多个 delta 和完整事件必须对应同一消息身份；
不能把每个 delta 自己的 event.id 当作新的消息或捕获身份。

引用使用完整目标，不仅是 basename：`./a/abc.png` 与 `./b/abc.png` 不应冲突。
编码保留 Markdown 解析后的原始目标，前后端不分别重写它。
用于源文件读取时才处理 URL 转义、query/fragment 和相对目录；
未知 cwd 的相对引用明确失败，不猜 HOME。
不按网络加载先后、文件显示名或路径猜测覆盖已有绑定。

### 相对产物路径

Copilot SDK 的 `session.workspacePath` 是包含 `files/` 的原生会话工作区，
与项目 `cwd` 不同。本体只转发这个 SDK 元数据，不决定或管理原生存储目录。
没有跨 harness 的统一“产物相对路径”标准，以下是本模块明确采用的兼容规则：

- 绝对路径和本地 file URL 使用其明确目标，不额外查找其他目录。
- 普通相对路径仍以原生 cwd 为基准。
- 规范化后位于 `files/` 下的相对路径（包括 `./files/...`），只检查项目 cwd 与 SDK 工作区下的同一相对路径。
  两处只有一处是可读普通文件时捕获；两处都有文件则返回 `AMBIGUOUS_SOURCE`，不猜优先级，也不按内容去重。
  两个候选恰好是同一个规范路径时只查一次。权限/非普通文件错误不等于“候选不存在”。
- SDK 工作区明确为空时只查 cwd；创建/恢复中的上下文尚未知时有界保留已识别引用，
  后续同消息事件带来工作区后再选择，保留链接出现时的 cwd，不重新扫描已处理文本。
  完整消息结束仍未知则明确报告，不用 HOME 或固定 `.copilot/session-state` 路径猜测。
- 不做全盘搜索，不去 `plan.md`、历史数据库或其他 session 中寻找匹配，不改变原生消息。
  路径歧义/缺失已记录后，历史读取和“重试预览”不会重新捕获当前文件。

前端始终用相同的 session/message/**原始 Markdown 目标**生成 URL。
真实源来自哪个目录只影响后端捕获；两者最终都绑定到该 URL 下的不可变快照，
前端无需判断 cwd/workspace，不需要修改 Markdown 或获得真实源绝对路径。

## 4. 每次交付固定一个版本

```text
消息 A -> ./report.csv -> 托管版本 V1
消息 B -> ./report.csv -> 托管版本 V2
```

- 每次真正的新用户上传保存新的文件记录。
- 每条新助手消息引用可变源文件，建立本次捕获绑定。
- delta 阶段已识别的引用可提前捕获；同消息同引用以首次成功提交的版本为准，
  完整消息到达时不再覆盖它。
- 同消息重放、刷新、两个浏览器访问，不重新读取源文件来覆盖旧版本。
- 同消息多次引用同文件可以共享本次快照。
- 首版不做跨文件内容去重，不同新上传/消息即使内容相同也保存独立原件；
  同消息同引用复用本次快照，仍保留必要的操作幂等。
- 前端收到路径/URL只负责读取；捕获和幂等提交由文件后端完成。
- 捕获保存的是实际读取时的字节，不承诺消息产生瞬间的原子文件版本。

模块后端的已选范围是：对本宿主已经加载的 session 实际收到的新回复通知尽早处理，
即使无人打开网页。边界从模块实际加载启用开始，不以安装包下载时间或浏览器首次见到消息计算。
翻旧历史只查已有文件绑定，不补上传、不回读源文件、不做旧数据兼容。
已经捕获的文件仍可在历史中查看；未捕获的旧引用明确不可用。
不能把会话恢复或事件重放误认成新输出；无法确认来源时不猜测补抓。
delta 丢失或中途改写的链接属于 best-effort 边界；新消息的完整事件可以补漏，
但不能恢复没有捕获到的旧文件字节。临时链接后来消失时，可能已经产生额外托管文件，
不能为消除这个现象去改原生消息或默认自动删除文件。
不为文件捕获加载所有会话、扫描全部历史或增加原生保活。
模块未运行期间的旧文件若已变化或删除，不能从 Markdown 链接还原旧字节。
完整的无内容去重、可靠提交与保留规则见[存储与生命周期](storage-and-lifecycle.md)。

## 5. 卡片读取与模型输入分开

图片上传并保存在服务器后，优先作为原生 `file` 附件交给 Copilot。
SDK 也支持 Base64 `blob`，但文件已经有可读路径时，不必先整读为 Buffer 再转 Base64。
图片支持范围与模型是否有视觉能力仍由原生 runtime/模型决定。

托管文件先通过 FileProbes HEAD 检查元数据，点击预览才使用原 URL 加载媒体，不自动下载缩略图。
草稿/原生附件用独立附件行，Markdown 链接与图片引用保持可折行的行内链接，
具体排版、错误与动作规则只在[前端契约](frontend-contract.md#2-可注册的位置)维护。
选择中的本地图片使用当前视图作用域的 object URL；托管媒体不整读为客户端 Blob。
音视频显式展开播放，HTML/PDF 不内嵌；代码/文本及源码行号定位仍不支持，只提供详情和下载。
新上传/捕获的 SVG 按字节识别为图片，按需预览使用 img，不把 SVG 文本插入页面 DOM。
SVG 响应保留 sandbox 和默认禁止外部资源的 CSP，仅允许绘图所需的内联样式；
脚本、事件处理器和外部资源不是预览能力的一部分。下载仍保留原始字节。
识别限于前 4 KiB 内的 SVG 根元素，可带 UTF-8 BOM、XML 声明和注释；
DTD、外部样式处理指令或超长前导内容不主动解析，未识别时仅提供下载。
旧快照保留其原有 MIME，不因浏览历史而重新捕获或修改原件。
浏览器能播放或预览，不代表模型能够理解该格式。
普通网页链接、示例代码中的路径和非托管本地路径不自动成为可下载文件。

原生消息中的 blob 已带 Base64 字节时，在浏览器内按文件大小上限有界解码，
使用临时 Blob URL 展示适用的图片/音视频预览或下载；不再上传、不发 HEAD 请求。
字节缺失或包含 omittedReason 时保留不可用卡片，不伪造空文件，不向历史补抓数据。
Blob URL 在内容变化、组件卸载或模块停止时释放；预览等待同样有五秒上限。

已知文件仍在准备时显示 loading；文件缺失、捕获失败、无权限或预览不支持时分别反馈。
加载完成后的重新请求需要模块自己的资源读取约定，不能依赖浏览器自动重试。
每轮 HEAD 状态检查为五秒，显式打开的媒体预览另有五秒加载期限；
明确失败可提前结束，检查超时不能推断原件不存在。
自动请求不重新生成文件版本，也不让旧消息进入补捕获流程。
本体不因此更改原生消息，也不让插件渲染错误破坏普通文字聊天。

## 6. 数据所有权

文件 bytes、快照与引用索引属于模块；原生 session、消息、历史和队列属于 Copilot。
服务端文件数据位于 `.cockpit/modules/data/cockpit-file`，
具体存储结构见[安装文档](installation.md)。
用户文字与附件草稿仍属于浏览器；浏览器文件二进制不放 sessionStorage。

通常从草稿移除不是删除原件。唯一例外是用户显式丢弃本次前端激活发起、
从未暴露给原生 pending 的未使用上传：先立即移除草稿项/中止上传，
再按内存中记录的上传 operationId 请求 DELETE；不从 fileId、捕获 ID 或原生 path 推断资格。
资格观察独立于视图挂载，pending 出现后永久放弃既有操作的删除资格；
pending 期间新增上传也受保护，刷新恢复的附件没有资格。
删除请求失败必须报告，但不恢复用户移除的草稿项；它不是通用引用计数/垃圾回收，
也不会在刷新、模块释放或成功发送时自动运行。
删除 session 不级联删除托管文件，
模块升级/卸载也不默认清除用户文件。明确删除后的资源不得因旧消息重新渲染而偷偷恢复。
删除托管原件也不等于从 Copilot 历史或模型上下文中撤回内容。
