# 首版后端设计

**当前源码已实现，尚未正式发布。** 本文描述首版后端分工。
实际入口、配置和路由见[构建与安装](installation.md)，公共接口为 Module API v1。

## 1. 范围

首版只完成两条链路：

```text
用户上传 -> 保存文件 -> 返回原生附件 -> 本体发送 -> 原生附件 path 映射为可读 URL

新实时回复 -> 流式识别文件链接 -> 复制为快照 -> 绑定消息/引用 -> 卡片按约定 URL 读取
```

只处理文件模块实际加载启用后的新上传、新实时消息。
历史浏览仅读取已有文件，不补捕获、不扫描历史、不做旧数据兼容。
全局文件库、汉堡菜单管理页、列表搜索和管理删除接口在 [Roadmap](roadmap.md)，本次不做。

## 2. Cockpit 本体提供三组通用能力

| 通用能力 | 责任 |
| --- | --- |
| 模块冷加载与资源归属 | 主进程 import、配置/兼容校验、贡献暂存和加载结果；不把文件处理业务放进 core |
| 命名空间 HTTP/静态资源 | 开始监听前统一挂载模块 API 和前端 JS/CSS，沿用宿主的认证、来源与错误边界 |
| 只读原生事件出口 | 在现有 SDK 通知的所有权检查之后向模块分派所需消息和生命周期事实，不新增历史轮询 |

模块不直接修改根 Fastify，不通过任意 onReady/onClose 改变宿主启动或退出。
初始化失败不能留下半注册路由；宿主负责装配与失败归属。
主进程 import 是可信代码协作，不是进程级故障沙箱。

发送原生 attachments 已有后端通路，本体继续执行唯一的发送动作。
文件模块后端不管理浏览器草稿、不发送隐藏消息、不重新组装模型上下文。
模块若使用本体公开 API，必须遵守相同原生准入和结果语义，不能绕过关闭限制。

文件首版无需“上传/发送文件”MCP 工具；通用 MCP 挂载不是上述两条文件链路的前置。

## 3. 文件模块的四个业务部分

### A. 托管存储

负责临时文件、原件、文件元数据，以及必要的消息引用绑定。
数据放在 `.cockpit` 的模块数据目录，与不可变代码包分开。

需要两类记录，不是第二份聊天库：

| 记录 | 必需内容 |
| --- | --- |
| 文件 | fileId、内部存储名、显示名、内容类型、大小、摘要、创建时间及可用状态 |
| 捕获 | 稳定原生消息身份、规范文件引用、捕获状态、对应 fileId、必要错误与来源信息 |

原件只在可靠写入后成为 ready，不发布半文件。
不同新上传和不同新消息产生独立业务身份，同名文件不覆盖；
同消息同引用重复触发使用已有记录，不能重新读取可变源覆盖旧快照。
首版不做跨文件内容哈希去重，即使字节相同，不同新上传/新消息仍保存独立原件。
摘要仅用于完整性；不建立共享对象池、引用计数和垃圾回收。

原子文件/元数据提交、私有目录、流式大小限制、并发和磁盘满处理可以参考旧实现，
但不恢复旧格式兼容和同步大文件读写。
进程中断后不能把未完成上传/复制当作 ready；恢复限于模块自身存储一致性，
不扫描原生历史或重新读取旧消息的源文件补抓。
存储状态、提交、恢复和保留的统一规则见[存储与生命周期](storage-and-lifecycle.md)。

### B. 用户上传

流式接收浏览器 File 字节，检查输入并保存，成功后返回：

```text
fileId
url
attachment: { type: "file", path, displayName }
```

上传结果意味着文件已经可用，不意味着消息已发送。
前端将原生附件加入草稿，由本体按正常 prompt 流程发送。

同一个上传操作的明确重试可以保持稳定身份，避免响应丢失产生重复文件；
不同的新上传不因同名或同路径被错误去重。
不在上传请求中管理 session 生命周期或修改原生历史。

可信调用方可通过 `DELETE /uploads/:operationId` 明确丢弃某个独立上传，不传请求体。
后端只使用上传操作身份，不接受附件路径或捕获身份，也不推断文件是否被其他会话引用。
它取消同根内可确认的本进程在途上传，并等待发布/清理结束；此请求不进入上传队列，
因此可取消占满工作槽的上传，也能提前阻止尚未开始的队列工作。
随后保存持久终态并以固定目录描述符移除该上传的原件和 ready 元数据。
同一身份不可复活，其他相同内容上传和消息捕获不受影响。
外部/未知 staging 所有者明确拒绝而不接管；请求断开不取消已开始的丢弃，关闭会跟踪其资源。
详见存储文档的终态、错误和保留边界。

### C. 新回复的流式捕获

使用本体已经收到的 SDK 事件，不新建每会话 eventLog.read。
典型事件是消息开始、正文 delta、同条消息的完整事件，以及结束/失效/卸载所需生命周期。
来源必须是模块启用后的新实时输出，不能把旧事件重放视为新消息。
无法确认来源或消息身份时不猜测补抓。

每条正在输出的消息有独立短期扫描器：

```text
feed(delta)
  -> 只扫描新字符
  -> 跨片段保留必要语法状态和未闭合候选
  -> 可识别链接出现
  -> 已处理目标：跳过
  -> 新目标：校验，先登记 pending，再异步复制
```

复制前根据链接出现时的原生工作目录和 SDK `workspacePath` 解析本地路径。
`files/...` 只使用项目与原生工作区两个候选，唯一存在时捕获，两处都有则明确报歧义；
不猜目录优先级、不全盘搜索。工作区上下文未知时有界延后，到完整消息仍未知则报告。
URL 身份保持原始 Markdown 引用，不把解析出的绝对路径反写给前端或 Agent。
按用户确认，来源允许服务用户可读的所有本地普通文件，包括本地符号链接目标。
只有新实时消息中的引用可触发捕获；HTTP 读取不能借此请求任意路径复制，也不抓取网络 URL。
托管数据的读取仍拒绝路径逃逸和符号链接替换。
不自动收集工具内部图片、思考或代码示例。

同消息同引用的并发触发由在途合并和持久唯一身份兜底。
新消息引用同一路径则重新捕获；首次成功快照固定下来，不追随之后的源修改。
完整新消息可做必要补漏，但不成为历史兼容路径。
解析状态在结束/卸载后释放，文件和绑定持久保留。

详见[消息观察与加载](observation-and-loading.md)：采用每消息流式状态机，通常文本扫描以近 O(N) 为目标，
内存只保留有界识别状态和必要去重，不承诺任意输入下总体 O(1)。

### D. URL 解析与文件读取

用户附件按 fileId/托管 path 读取；助手文件按消息/引用绑定读取。
两类地址最终进入同一个托管字节服务：

```text
托管 URL -> fileId ------------------+
                                   +-> 原件 -> 预览/下载
消息引用 URL -> 已登记捕获 -> fileId -+
```

前后端共用规范 path/URL 和消息引用编码函数，见[文件引用与地址](file-references.md)。
URL 可确定性生成，不代表后端一定有文件；未捕获的旧引用明确失败。
读取接口只做查询/读取，不从客户端 URL 解出任意源路径就创建捕获。

字节服务负责 Content-Type、Content-Disposition、长度、Range 和合适的缓存策略。
展示名不影响磁盘寻址；危险内容不能作为拥有宿主权限的页面执行。
浏览器预览与模型附件输入分开，不把大文件放进 JSON/SSE。

## 4. 最小 HTTP 能力

下列为能力分类，不是最终路由命名：

| 方法/能力 | 输入 | 结果 |
| --- | --- | --- |
| POST 上传 | 文件流、显示名、必要的上传操作身份 | 已就绪的 fileId、URL、原生附件 |
| DELETE `/uploads/:operationId` | 上传操作身份，无请求体 | 丢弃成功/重复成功 `204`；不删除捕获 |
| GET/HEAD 托管文件 | 规范托管文件身份 | 可用性/原件；GET 支持必要 Range |
| GET/HEAD 消息文件 | 稳定消息身份和规范引用 | 绑定对应的可用性/原件 |

大小、类型等少量信息可以通过响应头或按需的单文件信息接口提供。
不为首版增加文件列表、搜索、会话文件归类和全局管理删除接口。
已丢弃上传的普通 GET/HEAD 返回 `404`，同 operationId 再上传返回 `410`，
错误 JSON 沿用 `{ code, error, fileId?, committed? }`。非法身份为 `400 / INVALID_INPUT`，
未知在途所有权为 `409 / ACTIVITY_UNKNOWN`，并发上限为 `503 / BUSY`，存储/清理失败为 `500`。

前端卡片按 URL 合并 HEAD 探测，202/404 在五秒预算内退避重试，ready 后加载原 URL。
明确失败提前结束，整个自动 loading 总预算最多五秒，不因重绘/delta/重试重置。
不存在不能无限伪装为 pending，暂时未就绪响应不能长期缓存。

五秒是卡片本轮等待限制，不是所有上传/复制/下载的统一超时。
卡片读取重试不重新发送原生消息、不触发新文件捕获；
卡片超时也不代表共享后端捕获一定失败。

## 5. 运行与成本边界

- 使用本体已有的 SDK 通知，没有浏览器也可处理已加载 session 的新输出。
- 不因文件模块增加原生会话加载、历史拉取、保活或模型调用。
- 新增成本是当前消息识别、少量状态和实际文件复制，不是零成本。
- 解析/复制有界，异步 I/O 不进入同步 SDK 回调，不阻塞原生正文和 ACK。
- 文件上传、捕获和下载不参与 graceful 的 native busy 等待。
- 关闭时撤销模块资源作用域；不等待模块业务队列或异步 close 回执。
- 既有原生会话与附件路径由 Copilot 使用，模块不能假称对同用户原生工具实施文件沙箱。

## 6. 本体不承担的文件业务

本体不知道“哪个链接是文件”、文件如何落盘、哪个 fileId 对应哪个版本，
也不需要文件卡片状态 SSE、正文替换器或文件上传 MCP。
它提供通用接入点；文件模块实现流式识别、快照存储和读取。

用户上传、原生附件、流式捕获和五秒加载反馈已接通；
当前边界与后续能力分别见安装文档和 roadmap。

## 7. 模块包、配置与更新

文件模块以一个固定版本包交付后端 ESM 入口、前端 ESM/CSS 和必要资源。
静态声明至少说明稳定 moduleId、版本、宿主兼容条件及实际入口；
字段和导出函数以宿主 `packages/module-api/src/index.ts` 及 manifest 校验为准。

| 交付条件 | 要求 |
| --- | --- |
| 依赖 | 后端实际运行依赖随模块交付；不依赖另一个工作树或宿主未公开的传递依赖 |
| 前端运行时 | React/JSX runtime、主题和公共 SDK 由明确契约共享，不偷偷再打包一个应用根 |
| 数据根 | 宿主提供实际模块 data root；目录独立于代码版本，不在模块内猜真实用户 HOME |
| 配置 | 只接收当前实现支持的字段，非法路径/上限明确失败；待定限制不能冒充已有默认值 |
| 初次启用 | 校验后冷启动加载，实际成功注册才声明可用；下载安装与运行生效分开 |
| 更新/停用 | 下次宿主启动应用，当前进程不热换代码；已有原件和绑定不自动删除或迁移 |
| 浏览器版本 | 前端静态地址绑定固定模块版本；不兼容的旧页面明确提示，不混用新旧模块接口 |
| 实际安装 | 可信模块下载/验证/选择属于宿主通用能力，文件模块不实现另一个安装控制器 |

本仓库可构建供本地安装的 `.tgz`，但未创建正式 Release，
没有自动升级或生产部署流程。安装依赖支持 API v1 的宿主，不兼容已发布的 Cockpit v0.1.0。
