# 存储、幂等与生命周期

**当前实现。** 首版不做跨文件内容去重；消息/操作幂等、完整性与可靠保存仍保留。
内部 JSON 不是用户编辑接口；准确目录见[安装文档](installation.md)。

## 1. 代码和用户数据分开

模块代码版本目录不可变，用户文件在 `.cockpit` 的模块数据目录中。
安装模块与本体启动使用一致的 Cockpit 数据根；原生会话和认证继续遵循 Copilot 自己的配置。
文件模块不能通过改变整个进程 HOME 来改变 git/SSH 等其他工具语义。

逻辑布局示意：

```text
.cockpit/
  <模块数据根>/<moduleId>/
    files/                    已提交原件
    metadata/                 文件和捕获元数据（可以是其他已选存储形式）
    tmp/                      未完成上传/复制
```

具体目录名未定。不为未来功能创建空文件库数据库、缩略图服务或归档目录。
原生 session-state 和聊天数据库由 Copilot 管理，文件模块不直接读取它们。

## 2. 两类业务记录

| 记录 | 作用 |
| --- | --- |
| 文件记录 | fileId、内部存储名、显示名、类型、大小、创建时间、摘要和可用状态 |
| 捕获记录 | 原生消息身份、规范引用、对应 fileId、状态、捕获时间与必要错误/来源 |

展示名不是路径权威；路径由模块根和自身受控存储名派生。
捕获记录保存文件的来源关系，不保存完整回复、原生分页 cursor 或全部会话清单。
字段和具体 schema 在实现时确定，不为了索引补读整套 native metadata。

## 3. 不做内容去重，但保留操作幂等

以下是不同问题：

| 情况 | 首版行为 |
| --- | --- |
| 同一次用户上传的重复请求 | 使用同一操作身份，确认同一提交结果，不盲目生成另一个文件 |
| 同消息同引用被多个 delta/消费者遇到 | 使用同一捕获身份，只保留本次成功快照 |
| 用户主动再次上传相同内容 | 新文件记录和独立原件，不比较全库内容进行合并 |
| 新消息引用相同源路径/相同内容 | 新捕获和独立原件，不跨消息共用字节 |

消息身份、上传操作身份和内容摘要互不替代。
首版不建立内容寻址对象池、不按哈希合并文件、不为此加入引用计数或垃圾回收。
同一文件已在同条消息成功捕获，多次展示复用它，这是同一业务对象的重复读取，
不是跨文件内容去重。

SHA-256 在上传/复制流经过时计算，记录实际保存字节的摘要。
它用于完整性，不是 fileId，不是文件是否来自可信发布者的证明。
不为了摘要再同步整读大文件；读取时何时复核完整性须有明确策略，
不能因预览、HEAD 或视频 Range 反复同步读取整份原件。
当前还保存原件的设备/inode/大小/mtime/ctime 特征，读取时拒绝已变化的原件，
不在每次读取时重新计算全文件哈希。搬迁/恢复不属于首版自动兼容能力。

## 4. 文件提交

共同流程：

```text
校验输入与操作身份
  -> 私有临时文件
  -> 流式写入并累计大小/摘要
  -> 确认完整写入，完成必要的持久化
  -> 提交文件记录与引用绑定
  -> 对外 ready
```

文件字节、元数据和绑定必须形成可判断的提交边界。
若介质不能一次原子提交全部内容，需要明确提交顺序和中断恢复规则；
不允许半文件或缺失的记录被读作 ready。

复制助手文件时使用经过验证的普通文件来源与读取句柄。
若检测到读取期间文件发生变化，明确失败，而不是宣称获得了发送瞬间的原子快照。
摘要证明保存了哪些字节，不证明这些字节一定是原文件某个历史时刻的完整版本。

当原件已经提交，后续清理临时项或返回响应失败时，不能把已保存结果抹掉，
也不能引导调用方换身份重传。应保留可查询的操作结果和必要文件身份。

## 5. 状态与重试

| 状态 | 含义 |
| --- | --- |
| preparing | 模块已确认并登记这次工作，但还没有可用原件 |
| ready | 原件及所需记录已经提交，可按稳定地址读取 |
| failed | 本次操作明确未形成可用结果，保留可操作错误 |
| 结果未确认/中断 | 尚无法确认提交边界，不伪装为 ready 或可安全换身份重试 |

名称是逻辑状态，不是已发布 wire enum。
只有内存中的 Set/Map 不足以防止并发或重启重复发布，成功结果须由持久身份确认。
重新收到相同引用不等于新的复制授权；卡片读取重试也不是捕获重试。

当前助手捕获失败会保留结果，不因后续相同链接或卡片重试自动重开源文件。
已中断或无法确认所有权的旧 pending 记录以 INTERRUPTED/ACTIVITY_UNKNOWN 反馈，
不持续回读源文件来声称恢复了原版本。
首版不从历史阅读或资源 GET 触发任何补捕获。

## 6. 失败表现

| 情况 | 必须保留的事实 |
| --- | --- |
| 上传断流/大小超限 | 不发布部分文件；前端不把该附件视为就绪 |
| 磁盘满/权限不足 | 明确存储失败，不删除其他原件腾空间 |
| 原件提交后上传响应丢失 | 通过同一上传身份确认结果，不自动重复创建 |
| 助手路径不存在/来源目录未知 | 明确失败，不回退读宿主 HOME、不任意扩大访问根 |
| 文件复制中变化 | 不假称版本一致，保留失败信息 |
| 已捕获文件后来丢失/损坏 | 读取失败，不重新读取源路径替换历史快照 |
| 卡片五秒超时 | 只是本轮读取未及时成功，不自动删除文件、取消共享捕获或重发消息 |
| 模块/进程中断 | 不完整状态可判断，不把未提交记录升级成 ready |

恢复只处理模块自己的提交一致性。不得在启动时扫描 Copilot 历史或补抓旧引用。
模块缺失期间产生的消息不导入；模块再次启用也不回填这段历史。

## 7. 读取保护

文件服务只接受规范托管身份或已登记的消息引用，不接受任意路径读取指令。
同一 URL 指向确定原件，path/URL 的互逆仅在模块托管命名空间内成立。

必须处理：

- 托管路径穿越、编码歧义和托管目录/文件的符号链接替换。
- 非普通文件、危险显示名和错误的客户端 MIME 声明。
- 非法/越界 Range、长度和不完整响应。
- 用户文件不得作为拥有宿主权限的脚本/HTML 页面执行。
- 上传、复制、解析、连接和临时磁盘占用有明确上限。

这些属于文件业务必要的资源边界，不等于本体提供了同用户安全沙箱。
来源允许服务用户可读的本地普通文件；这与拒绝任意 HTTP 路径导入是不同边界。
支持类型和限制值见安装文档。

## 8. 保留与关闭

首版无全局删除管理、自动过期或无人引用文件回收。
从草稿移除附件不删除原件，删除 session 不级联删除文件，
模块更新/卸载默认保留数据。删除策略后续与文件库一起设计。

原生附件可能在后续才被读取；prompt ACK 不证明原件已可安全删除。
从磁盘删除托管文件也不等于撤回 Copilot 上下文中的内容。

宿主进入 closing 时撤销模块入口、监听和资源作用域，
不等待文件上传、复制、下载或模块关闭回执。
文件模块平时就完成可靠提交，不能依赖 async onClose 获得最后保存窗口。
本体仍等待它实际拥有的原生工作；文件业务本身没有额外保活权。

备份/搬迁时，模块原件和元数据需要作为一致的集合对待，
原生会话数据仍按 Copilot 自身规则管理。只备份原生历史不能恢复模块原件，
只复制文件字节也不等于恢复了消息引用绑定。首版不实现备份/迁移工具。
