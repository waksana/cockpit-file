# 前端接入契约

**当前源码：Module API v1。** 实际公共类型由 Cockpit 的 `packages/module-api` 提供，
模块入口是 `activate(context)`；整体尚未正式发布。
首版范围是聊天中的上传下载、附件与预览。全局文件库与管理页面进入
[Roadmap](roadmap.md)，不包含服务器项目文件编辑、移动或删除。

## 1. 最小分工

| Cockpit Web | 文件模块 Web |
| --- | --- |
| 页面和组件注册、路由、布局、共享 React 与主题 | 首版的上传按钮、附件列表、FileCard 和预览内容；文件库页面延后 |
| 当前 session/草稿上下文、受控字段修改、发送阻止 | 接收文件、上传、将就绪附件加入对应草稿 |
| 唯一发送动作、提交快照和晚 ACK 处理 | 不自动发送、不接管发送按钮、不维护投递队列 |
| 原生消息身份、附件和正文的只读展示输入 | 按规则将原生附件或 Markdown 引用渲染成文件组件 |
| 取消、作用域释放、错误反馈和阅读位置 | 业务上传状态、预览失败表现及文件操作 |

前端以“后端按约定准备对应文件资源”为契约前提，但不假设首次请求时已经 ready。
它按 best effort 识别引用、生成地址并渲染；资源未准备好时卡片保持 loading，
不负责捕获助手文件，也不在 React render 中触发上传。
不需要额外的宿主展示资源协议或文件状态 SSE。
每次卡片自动等待最多五秒，通过 HEAD 探测后加载原 URL；
具体行为见[消息观察与加载](observation-and-loading.md)。

## 2. 可注册的位置

| 插口类别 | 注册内容 | 文件模块首版 |
| --- | --- | --- |
| 全局菜单和页面 | 后续的汉堡菜单项与页面注册 | 当前宿主 API v1 未提供，文件库延后 |
| 单会话菜单和页面 | 后续的 session 菜单项与页面注册 | 当前宿主 API v1 未提供，本模块不使用 |
| 输入栏按钮 | 输入框前后可排列的操作按钮 | 上传按钮 |
| 输入栏上方组件 | 保持在当前草稿作用域内的组件 | 待发送附件列表、上传状态 |
| Chat 渲染插件 | 原生附件、Markdown 链接或图片等只读输入的匹配与渲染 | FileCard 和图片/媒体预览 |

注册声明至少包含模块内唯一 ID、目标类别、组件和必要的标题/顺序。
公开位置是有限的语义插口，不是私有 CSS 选择器或任意 DOM 地址。

行为要求：

- 本体负责确定顺序；同身份冲突明确拒绝，不按加载速度决定。
- 排他渲染规则冲突必须有确定的处理规则，不静默覆盖其他模块。
- 不命中的内容沿用本体默认渲染。
- 模块共用宿主 React、路由和主题，不再 createRoot 或启动独立 SPA。
- 模块不读取或写入本体私有 store，不依赖内部 DOM 结构。
- 宿主维护移动端收纳、键盘操作、弹层焦点和聊天滚动。
- 注册和解绑属于页面/模块资源生命周期，不代表允许运行中热安装或替换模块。

当前返回对象的能力字段：

```text
activate(context) 返回
  writes: ["attachments"]
  composerActions: 上传按钮
  composerAbove: 附件列表
  rendersDraftAttachments: true
  fileInput: 文件选择、拖放、粘贴
  chatRenderers: 原生附件、Markdown link/image
```

前端使用 `context.react`，不打包第二份 React；通过 `context.request`
访问本模块 API，沿用宿主 origin、部署前缀、凭据和摘要校验。
不返回 globalPages/sessionPages 等未实现字段，宿主会明确拒绝未知贡献。

不要求文件模块为了接入这些位置维护另一套路由、消息监听或重连机制。

附件展示通过 `composerAbove` 与 `rendersDraftAttachments: true` 显式声明；
宿主因此不重复渲染原生草稿的基本附件列表，模块失败时才恢复基本列表。
上传入口使用 2.5rem、透明无边框的圆形图标按钮，保留 tooltip、可访问名称、
键盘焦点和禁用状态；只复用合适的视觉样式，不依赖本体私有 DOM、store 或旧上传实现。
草稿、聊天和原生 blob 共用固定 17.5rem x 4.5rem 的三列卡片（默认 280 x 72px，最大宽度 100%），
所有状态保留相同结构与尺寸，不因动作或正文长度收缩。
左侧 3rem 缩略图/文件图标等比例完整显示；中间单行文件名和单行状态，活动条使用固定预留位置；
右侧 4rem 操作区至多两个图标按钮，下载、移除和重试不再挤在文字下方。
长名省略并尽量保留有界的扩展名，连续无空格、无扩展名和超长扩展名都不能撑破布局。
名称及错误为可聚焦按钮，点击打开完整详情，不依赖桌面 hover；完整错误不在卡片内增加行数。
草稿多项可换行，消息内排列继续由宿主决定，模块不覆盖宿主容器样式。
草稿提供移除和失败重试，聊天提供下载；图片点击缩略图后才在可关闭的原生 dialog 中放大，
音视频通过显式播放入口展开，不默认撑大气泡，不内嵌 HTML/PDF。

## 3. 可接收的上下文

本体提供绑定生命周期的只读上下文：

| 场景 | 必需信息 |
| --- | --- |
| 全局页面 | 模块路由、返回位置；从聊天进入时可携带目标草稿句柄 |
| 会话页面 | 明确的原生 session 身份 |
| 输入组件/事件 | 绑定的 session/草稿句柄、当前操作类型、输入可用性 |
| 消息渲染 | 后端提供的稳定消息身份、原生 session、正文完整/流式状态、附件描述 |
| Markdown 渲染 | 实际 link/image 节点的目标和显示文字，以及所属消息上下文 |

异步上传必须持有开始时的草稿句柄。用户切换会话后，不能重新读取“当前 session”
并把旧上传结果加入新会话。
视图卸载与草稿释放是不同生命周期：切换页面可以释放视图监听，
不能因此丢掉仍由原草稿持有的上传结果或提前解除发送阻止。

消息身份、列表下标、DOM key 和模块 fileId 是不同概念；具体规则见
[文件引用与地址](file-references.md)。

## 4. 输入事件

点击选择文件、拖放和粘贴必须汇入同一个上传入口，避免三套逻辑。

| 事件 | 本体负责 | 模块负责 |
| --- | --- | --- |
| 选择文件 | 提供正常的按钮/手势生命周期 | 在用户点击栈中打开选择器，得到 File 列表 |
| dragover/drop | 在聊天输入区域分派事件，协调是否消费 | 识别文件项并提交到上传入口 |
| paste | 保持文字输入和输入法行为，协调文件项归属 | 接收剪贴板图片/文件，进入上传入口 |
| 草稿变更 | 提供当前快照和受控修改方法 | 读取自身需要的内容，刷新附件列表 |
| 作用域释放 | 取消订阅、撤销该作用域的操作资格和阻止项 | 释放 object URL、临时视图资源等 |

约束：

- 没有文件时不拦截普通粘贴；混合文字和文件时不得吞掉文字。
- 不能注册全页面粗暴拦截，影响其他页面或其他模块。
- 同一批文件只交给一个选中的处理器，不能多个插件各上传一次。
- 未明确处理前不无条件 preventDefault。
- 选择器必须由真实用户手势打开，不能在异步 HTTP 完成后伪造手势。
- 输入法组合输入、普通回车和发送快捷键仍由本体处理。

## 5. 原生字段与草稿修改

已核对 Cockpit 使用的 SDK **1.0.13**：
`MessageOptions.attachments` 原生支持 `file`、`directory`、`selection` 和 `blob`。
文件示例：

```ts
{
  type: 'file',
  path: '/srv/cockpit-data/managed/opaque-file-id.png',
  displayName: '页面.png'
}
```

`path` 属于 Copilot runtime 所在机器，不是浏览器本地路径。

在 Cockpit 基线
[`97f8e75`](https://github.com/waksana/cockpit/tree/97f8e75c65fbf18b9e3c85ca562c46d8db6f1990)：

- `packages/protocol/src/index.ts` 已定义 NativeAttachment 和 prompt.attachments。
- Web 网络层、store 和后端已能把附件传给 SDK。
- textDraft、Composer 和 Thread 的 UI 接线仍只处理文字，需要补齐。
- 当前 prompt 上限是 20 项附件；模块选择器不能与最终发送上限冲突。
- 原生事件中的附件描述与发送输入不完全等形，接入时不能不经适配就互相强制转换。

模块声明要修改的公共草稿字段，例如：

```ts
{ writes: ['attachments'] }
```

本体提供绑定草稿的追加/移除方法，不暴露任意 store.setState。
当前方法为 getSnapshot/subscribe、appendAttachments/removeAttachment、editText 和 block。
快照中的每个就绪附件带本体协调所需的 `{id, value}`，其中 value 才是原生 NativeAttachment；
本体发送时只发送 value，不把 UI 身份带入原生协议。
声明用于接口校验、协作和作用域约束，不是同进程插件的安全沙箱。
普通文字由本体保留；其他模块需要编辑文字时使用单独声明的文字接口。

文件模块应当：

1. 上传并得到已就绪的托管文件。
2. 获取或转换成 SDK 原生附件。
3. 将附件追加到绑定草稿的 attachments。
4. 通过原生附件数组让本体正常发送，不插入私有正文标记。

上传进度、File 对象、object URL、重试状态不写进原生 attachments。
文字和就绪附件描述只由宿主 SessionDraft 的原生草稿持久化负责；
文件模块不维护第二份浏览器存储，也不保存文件二进制或未完成选择的元数据。
刷新后丢弃全部上传中、上传失败及尚未成功加入草稿的选择和对应发送阻止；
不恢复占位项，不导入或清理旧的模块上传缓存。需要继续上传时，用户重新选择本地文件。
每个已确认的上传结果应立即加入捕获的宿主草稿，不等待前面的文件成功：
选择 A、B 而 B 先完成时，刷新前草稿已持有 B，刷新后仍可恢复 B。
就绪文件只通过草稿 attachments 展示一次，不再重复出现在上传中的列表里。

选择中的图片通过当前视图持有的本地 object URL 显示缩略图；
就绪及从宿主恢复的托管文件改用规范服务端 URL 和既有 FileProbes HEAD 探测，
不为了预览将整份托管文件转为客户端 Blob。视图卸载、资源变化和模块释放均回收本地 URL；
切换视图不取消原草稿中的上传任务。
每个未完成项内部显示上传状态及无 `value` 的不定进度条，不伪造 fetch 无法提供的上传百分比。
正常上传没有底部“请等待”提示或全局红框；真正的校验错误、上传失败和重试操作仍清晰可读。

显式移除先立即更新草稿/取消当前上传并释放相应阻止，不等待网络删除。
仅本次 UploadStore 激活自己发起、从未暴露给原生 pending 提交的上传操作有资格
调用 `DELETE /uploads/:operationId`；该调用只接受 204 成功，其余响应或网络失败通过
`context.report` 报告，不撤销用户的草稿移除。此处是“丢弃本标签页尚未使用的上传”，
不是通用引用计数或垃圾回收系统。
资格独立于排序条目保存在有界内存映射中，不持久化、不保留成功上传的 File。
对捕获的 draft.subscribe 的观察独立于组件挂载；只要看到 pending，
已有/进行中的上传即永久失去删除资格。pending 期间不接纳新上传、移除或重试，
上传按钮、文件选择器和所有移除/重试按钮置灰；延迟的选择器和拖放/粘贴事件也不能绕过。
收到回执后恢复附件操作，不等待 Agent 回合结束；文字编辑不受影响。
移除时同步再检查 pending，不以未确认原生提交的结束或失败恢复资格。
刷新恢复的附件、任意原生路径和助手捕获 ID 没有资格；也不因刷新、模块释放、成功发送
或宿主自行清理草稿而自动删除原件。已取消操作的晚结果不得重新加入草稿。

## 6. 发送阻止和唯一提交

上传和加入草稿失败的反馈留在对应文件项内，不再重复触发全局错误通知。
已经移除的文件若异步删除失败，由宿主反馈出口报告，因为此时已没有文件项承载错误。

上传开始时，本体必须知道该草稿暂时不能发送。
可以提供按所有者登记的发送阻止项，而不是一个所有模块共同覆盖的全局布尔值。

```text
为本批文件登记阻止项
  -> 预留附件位置并开始上传
  -> 每个上传完成后立即将对应附件加入草稿，按选择顺序调整已就绪项
  -> 所有未解决项成功或被明确移除后释放阻止项
```

- 同一批文件的位置和阻止项须在异步上传前建立，避免瞬间误发送。
- 并行上传中，一个文件完成不能解除其他文件的阻止项。
- 当前页面中，上传中及失败但仍保留的选择继续阻止发送，直到重试成功或用户明确移除；
  普通移除最后一个未解决项即可解除本模块的阻止，不影响其他模块的阻止项。
- 交叠的多次选择仍保留原始选择顺序。使用 appendAttachments 的按 ID 更新后追加语义，
  仅重排仍在草稿中的本模块后续就绪项，不重新添加用户已经移除的附件，也不修改其他模块的附件。
- 附件上限同时计算草稿就绪附件和未解决选择；已加入草稿的成功项不能重复占用名额。
- 后端上传成功但加入草稿失败与上传失败明确区分；当前页面内重试加入草稿时复用已得到的原生附件，
  不重新上传文件。刷新后这类未加入草稿的选择也被丢弃。
- 同一 guard 覆盖发送按钮、Enter 和其他发送快捷键。
- 阻止项按草稿/session 和操作归属，不影响其他会话。
- 视图卸载或切换 session 不结束内存中的上传及失败选择；晚结果仍归原草稿。
  模块整体释放后取消未结束请求，晚回调不能再写草稿或恢复阻止项。
- 一般草稿移除只改草稿；只有上述显式、仍有资格的本页上传操作才另行请求丢弃原件。

用户发送时，本体一次捕获文字、就绪附件及其修订身份，执行一次原生调用。
允许只有附件而没有文字的普通 prompt。
原生 ask/plan-feedback 等操作若不支持附件，应明确阻止不兼容输入，
不能静默丢弃附件或擅自改为普通 prompt。
旁边存在工具 elicitation 卡片不会把文字编辑器的普通 prompt 改成 elicitation 回答；
编辑器操作类型跟随它实际调用的原生 API。

原生 ACK 只清本次提交的文字/附件，之后新增的内容保留。
未确认结果不自动重投；上传成功不等于消息已发送。
模块不需要另写 ACK 清理器或劫持发送按钮。

## 7. 两条渲染规则

### 用户原生附件

```text
原生用户消息 attachments
  -> 文件模块把托管 path 转为 URL
  -> FileCard
```

本体必须保留原生附件描述，纯附件消息不能被当成空消息丢弃。
file 附件只处理自身托管路径；不匹配的本地路径保留默认说明，不假造下载地址。
展示输入使用 NativeAttachmentDescriptor，不要求缺字节的历史 blob 满足完整发送参数。
blob 已带 data 时，在浏览器内有界解码并使用临时 Blob URL 显示预览/下载，
不上传、不执行 HEAD 探测。缺 data 或带 omittedReason 时直接显示不可用卡片，
不补抓历史或伪造空文件；本体无匹配模块时仍保留基本文字占位。
Blob URL 随内容变化、组件卸载和模块停止释放；预览五秒超时不影响原件下载。

### 助手 Markdown

```text
原生当前正文中已识别的 link/image（包括 delta 阶段）
  + 后端提供的消息身份
  -> 模块共享算法生成展示 URL
  -> FileCard 或图片组件
```

前端不需要从后端额外取得一份“消息到卡片”的推送协议。
文件名可来自 Markdown 文字/alt；如卡片需要大小、准确 MIME 等而原生输入没有提供，
可由模块自己按需查询，不扩张成宿主通用展示资源系统。

流式正文正常显示。只要当前 Markdown 已能识别链接/图片节点，即可按 best effort 渲染，
不等待原生完整消息；尚未构成可识别节点的片段仍显示为文字。
目标随后变化时跟随新的引用，旧引用的晚结果不能覆盖新卡片。
同一引用在连续 delta 中出现时保持组件和资源地址稳定，不反复启动相同请求。
渲染和刷新不能触发文件捕获；已知准备中的资源显示 loading，
不存在、捕获失败和无权限不能永久伪装为 loading，单次自动等待最多五秒。
重绘、后续 delta 和自动重试不能重置该引用的等待截止时间；显式重试可以新开一轮。
浏览旧历史时仍可按规则渲染卡片，但只读取已有资源，不通知模块补上传。
模块启用前或停用期间未捕获的文件可以失败，不回读源路径伪造旧版本。
失败保留原文与明确反馈，不能让整个消息白屏。

## 8. 不在本契约中增加的机制

- 任意 DOM 插入、整个应用替换、每个组件都可覆写的反射系统。
- 模块自己的原生消息读取、分页、重连和第二份聊天数据库。
- 前端按 token 正则扫描并上传文件。
- 通用展示资源图、每卡片 SSE、必须随 native event 发送的模块 sidecar。
