# 端到端验收清单

这些是后续实现的验收要求，**不是已通过的测试结果**。
使用合成会话和文件，不连接生产服务或读取真实用户数据。
优先复用 Cockpit 已有 runner、组件测试与 Chat Lab；
本仓库当前不新增测试框架或空构建工程。

## 注册与共享运行时

- manifest 的 entry/styles 均受现有 asset 根与摘要约束。
- 对所有草稿的非持久化 File 工作执行原生 beforeunload 保护；
  隐藏草稿、失败 File、插入失败结果仍提示，只有就绪附件不提示。
  用户取消离开不取消/删除工作；模块停止解除监听。浏览器平台限制不冒充可靠持久化。
- 首版不提供全局文件库、汉堡菜单文件管理项或会话文件页面；
  通用页面插口的完整能力与文件库实施不作为本模块首版验收前置。
- 上传按钮、输入框上方附件列表均通过注册接入，没有本体文件模块专用判断。
- 两个合成模块共同贡献按钮时顺序确定；重复 ID 与排他渲染冲突明确。
- 模块与宿主共用 React、路由和主题，不产生第二个应用根。
- 未启用模块时无入口，普通聊天可用；模块组件异常只影响自己的区域。

## 输入与上传

- 文件选择、拖放、粘贴图片使用同一个上传入口。
- 上传入口使用宿主公共图标按钮和 Lucide 图标，有 tooltip/可访问名称，
  不显示盒装“附件”文字，也不依赖宿主私有 DOM 或旧上传代码。
- 同一批文件只上传一次，交叠的多次选择也保留用户选择顺序。
- 纯文字粘贴、混合文字/图片粘贴和输入法行为不被破坏。
- 拖拽其他页面的内容不被全局处理器劫持。
- 上传中，发送按钮、Enter、快捷键均不能发出消息。
- 多文件并发时，先完成的文件不提前解除其他上传的发送阻止。
- 选择 A、B 而 B 先完成时，B 立即进入宿主草稿且只展示一次，A 仍阻止发送；
  A 完成后草稿顺序为 A、B，不能为了排序延迟 B 的持久化。
- 上传失败后可重试或移除；当前页面中未就绪项不能被静默忽略后发送文字。
  A 失败、B 已就绪时，普通移除 A 即保留 B 并解除本模块的阻止。
- 进度只在每个上传项内部以不定 `<progress>` 表示，不声称 fetch 提供百分比；
  正常上传没有底部“请等待”提示或全局错误横幅，真实错误和重试保留在项内。
- B 已就绪后从草稿移除 B，随后 A 完成或重试时不能复活 B。
- 后端上传成功但追加草稿失败明确提示；当前页面中重试复用原生附件结果，不重复上传。
- 上传中或失败后卸载视图、切换 session，内存状态及阻止仍归原草稿；
  晚结果不写入其他会话，不修改其他模块的附件、阻止项或原生发送状态。
- 已就绪附件与待处理选择共同遵守 20 项上限；成功项不能因保留排序信息而重复计数，移除后可复用名额。
- 模块整体释放后中止请求；晚回调、重试和移除不再写入草稿。
- 释放视图时正确回收 object URL、监听和相应作用域资源。
- 同名、相同内容甚至同一 File 的重复选择都有独立操作 ID、预览 URL 与移除资格。
- 显式移除立即取消/移除当前项，不等待 DELETE，不延迟解除自身发送阻止；
  只请求本次激活发起且从未暴露给原生 pending 的 `/uploads/:operationId`，重复移除不重复请求。
  后端未响应、失败、提交未确认或晚成功时，取消项都不能重新出现。
- 就绪项排序信息被裁剪后仍保留小型资格映射；独立观察捕获的 draft.subscribe，
  视图卸载/切换会话期间的 pending 仍永久保护已有上传。移除时也同步检查当前 pending。
  pending 期间上传、移除和重试置灰且处理器拒绝迟到输入，不改草稿、不上传、不删除。
  收到回执后恢复操作，但已暴露给原生提交的原件不恢复删除资格。
- 从宿主恢复、其他原生路径或助手捕获 ID 只能移除草稿引用，不能请求删除。
  DELETE 只有 204 算成功，非成功响应/网络错误必须 report；不因失败恢复已移除的草稿项。
  成功发送、刷新和模块释放都不自动删除原件；资格/监听可清理且不保留成功项的浏览器 File。

## 原生附件与发送

- 就绪附件符合固定 SDK 的发送 schema，使用服务器可读路径。
- 上传成功不自动创建消息；本体发送一次 text + attachments。
- 纯附件、无文字消息可发送并在历史中显示。
- 原生问答/计划反馈等不兼容操作不会丢掉附件或被替换为普通 prompt。
- 提交后新增的文字和附件不被旧 ACK 清理。
- 原生结果未确认时不自动重发；前端明确保留未确认状态。
- 刷新仅从宿主 SessionDraft 的原生附件恢复已就绪文件，不存在文件模块的第二份浏览器存储。
  上传中、上传失败和追加草稿失败的选择及阻止全部丢弃，不恢复占位项，也不导入或清理旧模块缓存。
  B 先于 A 就绪时，从当时的宿主草稿快照刷新可保留 B，但没有 A 的任务或发送阻止。
- 上传状态不写进 NativeAttachment；正文不插私有附件标记。

## 路径、URL 与渲染

- 完整原生 blob 在浏览器内解码并展示适用的预览/下载，不上传或请求模块 HTTP。
  缺字节、带 omittedReason 或数据无效时保留不可用卡片；纯附件消息不消失。
  Blob URL 在内容变化/卸载/停止时释放，重绘不重置五秒预览期限，旧媒体事件不覆盖新资源。
- 对规范托管路径和 URL，两个共享映射函数满足互逆关系。
- Unicode、空格、同名文件、类型后缀和编码边界明确；非托管输入不生成下载地址。
- 用户原生附件 path 可直接渲染卡片，不另依赖消息关联接口。
- 助手普通 Markdown link/image 使用后端稳定消息身份和完整目标生成资源 URL。
- 主/子 Agent、实时/历史中的消息身份一致，不使用渲染数组下标。
- 不解析代码块里的路径，不把普通网页链接自动下载入库。
- 后端在 delta 中识别到链接即可 best-effort 捕获；前端独立识别当前节点并在完整消息前渲染。
  尚无法识别的片段保留文字，前端渲染和重绘不会触发上传或捕获文件。
- 同消息的 delta 与完整事件共用身份；重复引用不重复复制，
  目标变化时旧请求的晚结果不覆盖新卡片。
- 未准备好的文件显示 loading；就绪后按选定的有界请求机制显示文件。
  每轮自动等待总计最多五秒，不因 delta、重绘或自动重试重置；
  失败/不存在/无权限可提前失败，隐藏卡片不永久轮询。
- 同消息刷新/重连保持相同资源；同路径在新消息中使用不同捕获版本。
- 文件卡片用于草稿和聊天，动作按场景区分；文件库复用放在后续阶段。
- 草稿/原生附件（含 blob）使用固定控制高度的附件行，Markdown link/image 始终是可折行行内链接；
  不扫描前后换行、不用私有 DOM 判断布局，不因资源状态变化切换模式。
  附件行最大 32rem 且不超容器，默认 40px/粗指针 44px；状态列与两个动作槽始终预留。
  加载、就绪、提交、失败等高，长名省略，完整错误和名称可通过触摸或键盘打开。
  行内引用继承段落字号与行高，无上下 padding、固定高度或不可拆分的胶囊；
  长路径可自然折行，前后及加载/错误时段落行高不变，下载/重试仅在弹窗提供。
  草稿就绪/上传中项由文件模块在同一列表中纵向排列，不覆盖宿主消息容器。
  本体不预建草稿附件组，不用全局布尔值隐藏列表；模块/schema 不可用时不参与原生发送，
  不生成文件兜底列表或恢复阻止。原生历史附件仍通过 attachment middleware 呈现。
- 选择中的图片使用可回收的本地 URL；成功/恢复后的图片使用规范服务端 URL 与 FileProbes，
  不把托管媒体整读为客户端 Blob。未打开预览前不创建 img/audio/video 或下载媒体；
  HEAD 就绪后无需媒体事件便停止检查。打开预览时才开始独立的五秒加载期限。
  不嵌套动作按钮，下载/移除不触发预览；预览重试只重开媒体，不重复捕获或解码原件。
  行主体按钮直接包含可见内容；行内链接有真实资源 href，修饰键/中键行为不被劫持。
  原生 dialog 通过公共 portal 挂到 body，不能嵌在 span/段落内；
  缺少 Web API v2、公共 UI v1 或 portal 的旧宿主明确拒绝激活。按钮尺寸、主题、焦点和许可遵守
  [宿主公共 UI 指南](https://github.com/waksana/cockpit/blob/main/docs/module-ui-guide.md)。
  音视频经显式播放入口展开，HTML/PDF 不内嵌。
- 检查超时明确可用性仍未知；预览失败保留已就绪原件的下载。
  短状态不撑开附件行，点击可读完整错误、重试；旧媒体/弹窗回调不覆盖新资源。
- 后端文件请求失败不隐藏原生正文，不造成整个聊天白屏。
- prompt 草稿与请求身份独立的回答草稿互不污染。ask 期间原 prompt 的文字/文件保留、
  回答草稿只显示禁用的上传按钮，不显示附件列表或接收文件；完成/取消后恢复，
  失败保留回答草稿，替换请求不继承旧答案。
- 文件 schema 的序列化空值优先于旧根 attachments，ACK 后不能再次导入旧附件。
  无效存储、投影冲突和旧 schema/draft 的晚回执明确失败，不伪造成功。
- 同一个 `files/...` 目标位于项目或 SDK 会话工作区时，前端原始引用 URL 均能读取唯一快照；
  两处同时存在必须拒绝捕获，缺失/不可读和非普通文件保持明确失败。
  SDK 工作区为空与暂不可用须区分，不硬编码 native home、不提示 Agent 改写输出。
- 新的托管 SVG 能通过原有图片卡片预览，服务端不按扩展名或浏览器 MIME 提示直接相信内容；
  按需预览使用 img，不执行内联 SVG DOM，响应 CSP 禁止脚本和外部资源，同时支持内联绘图样式。
  HTML、外部 DTD/样式处理指令及无法识别的字节不升级成可执行文档。
- 翻历史只查询已有资源，不启动捕获；没有快照的旧引用失败，不回读当前源文件伪造旧版本。

## 无人观看与资源成本

- 无浏览器时，只处理本宿主已加载 session 已收到的 SDK 通知，
  不新建 eventLog.read 长轮询或加载 unloaded 会话。
- 模块按当前正在输出的消息做短期识别与每引用去重，不保留全部原生聊天副本。
- 安装前/停用期间的旧消息、恢复重放、历史分页都不触发新的捕获。
- 完整消息/会话释放后清理不再需要的增量识别状态。
- 复制和解析不阻塞 SDK 回调；资源并发/内存有界，异常明确归模块。
- 上传、复制或卡片等待不增加宿主 graceful 的业务等待条件。
- 区分原有通知流量与模块新增解析/复制成本；没有负载测量时不声称零成本。

## 增量识别算法

- 同一示例按整条、逐字符和每个可能断点分片，跨片段链接均能在目标可识别时被发现。
- 保留必要的转义、代码围栏/行内代码、括号与多链接边界。
- 普通追加路径只扫描新字符，不对每个 delta 重扫完整累计正文。
- 同一消息重复链接只做一次目标解析和捕获；并发/重放不产生第二个成功版本。
- 同路径出现在另一条新消息中重新捕获，不跨消息只按 URL 去重。
- 完整新消息的纠正/补漏只处理未捕获引用，不覆盖先前成功快照。
- 长正文、长 URL、许多短 delta 和多会话交错场景测量扫描次数、内存和复制次数；
  未闭合候选/异常输入有明确资源上限，不能无限积累。

## 后端上传与存储

- 上传字节与后续读取/原生附件使用的原件一致；显示名不能决定任意磁盘位置。
- 新上传/新消息使用独立原件，即使内容和摘要相同；未引入全库内容去重或共享对象池。
- 同一上传操作或捕获身份重复请求，确认同一结果，不发布重复版本。
- 并发触发先登记工作再复制；仅内存去重不能替代持久身份约束。
- 大小超限、断流、磁盘满、权限不足和非法文件输入都不发布半文件。
- 文件提交、元数据提交、绑定提交和响应返回各阶段中断，均能明确区分 ready/未提交/未知。
- 已提交后清理或返回响应失败，不删除成功原件或诱导换身份重传。
- 模块重启只处理自己的一致性状态，不用历史扫描/源文件重新复制伪装修复。
- 复制期间检测到源变化时明确失败；已有原件损坏时不拿当前源文件替换。
- SHA-256 只作为完整性信息，不用作跨文件合并键；避免每次 HEAD/Range 同步重算整份大文件。

## 文件读取与边界

- 两类 URL 都只能读取已有托管记录；任意客户端编码的路径不触发复制或任意文件读取。
- 非法路径、符号链接逃逸、Unicode/百分号编码歧义、非普通文件和危险 MIME 明确处理。
- 下载字节、文件名、长度和支持类型符合实际文件；Range 的正常/越界响应正确。
- 未就绪响应不长期缓存；明确失败与等待中可区分。
- HEAD 与显式媒体预览分别有五秒等待预算；超时不取消共享捕获、不重发原生 prompt。
- 危险文件内容不获得宿主页面执行权限；统一认证和来源保护覆盖全部文件入口。

## 生命周期与交付

- 文件模块缺失、导入失败、无效配置或可归属的注册失败不会伪装成已启用；
  可处理的模块失败局部反馈，不留下半注册入口。
- 主进程模块不被宣传为进程级沙箱；无协作代码的阻塞/崩溃属于已说明风险。
- 只有模块上传/复制/下载时不增加 graceful 等待；
  已有真实原生回合/队列仍按宿主规则保护。
- 卸载/更新模块或删除 session 不删除托管原件；
  一般草稿移除只改变该草稿，仅显式丢弃本页仍有资格的未使用上传例外，
  不把该能力宣传为通用引用计数/垃圾回收。
- 独立模块包包含实际运行依赖，前后端同版本，不借宿主私有 bundle 或开发树文件。
- 模块可用性、源码完成、发布和线上启用分别报告。

## 不以外观代替接入完成

最终应以独立构建的模块包和真实宿主接口完成上述流程。
静态 HTML、手工插 DOM、伪造上传成功或依赖宿主私有代码路径，不算模块接入完成。
前端符合接口也不代表后端捕获、持久化、权限和快照已经正确；上述前后端与交付项须分别完成。
