# 前端验收清单

这些是后续实现的验收要求，**不是已通过的测试结果**。
使用合成会话和文件，不连接生产服务或读取真实用户数据。
优先复用 Cockpit 已有组件测试与 Chat Lab；本仓库当前不新增测试框架或空构建工程。

## 注册与共享运行时

- 全局汉堡菜单注册“文件库”并能进入、返回；从聊天进入后草稿不丢失。
- 文件模块不注册会话菜单页面；用合成贡献验证此通用插口可用。
- 上传按钮、输入框上方附件列表均通过注册接入，没有本体文件模块专用判断。
- 两个合成模块共同贡献按钮时顺序确定；重复 ID 与排他渲染冲突明确。
- 模块与宿主共用 React、路由和主题，不产生第二个应用根。
- 未启用模块时无入口，普通聊天可用；模块组件异常只影响自己的区域。

## 输入与上传

- 文件选择、拖放、粘贴图片使用同一个上传入口。
- 同一批文件只上传一次，保留用户选择顺序。
- 纯文字粘贴、混合文字/图片粘贴和输入法行为不被破坏。
- 拖拽其他页面的内容不被全局处理器劫持。
- 上传中，发送按钮、Enter、快捷键均不能发出消息。
- 多文件并发时，先完成的文件不提前解除其他上传的发送阻止。
- 上传失败后可重试或移除；未就绪项不能被静默忽略后发送文字。
- 上传中切换 session，晚结果只能回到原草稿。
- 释放视图时正确回收 object URL、监听和相应作用域资源。

## 原生附件与发送

- 就绪附件符合固定 SDK 的发送 schema，使用服务器可读路径。
- 上传成功不自动创建消息；本体发送一次 text + attachments。
- 纯附件、无文字消息可发送并在历史中显示。
- 原生问答/计划反馈等不兼容操作不会丢掉附件或被替换为普通 prompt。
- 提交后新增的文字和附件不被旧 ACK 清理。
- 原生结果未确认时不自动重发；前端明确保留未确认状态。
- 刷新可恢复已持久化的附件描述，未上传的浏览器 File 不被假装恢复。
- 上传状态不写进 NativeAttachment；正文不插私有附件标记。

## 路径、URL 与渲染

- 对规范托管路径和 URL，两个共享映射函数满足互逆关系。
- Unicode、空格、同名文件、类型后缀和编码边界明确；非托管输入不生成下载地址。
- 用户原生附件 path 可直接渲染卡片，不另依赖消息关联接口。
- 助手普通 Markdown link/image 使用后端稳定消息身份和完整目标生成资源 URL。
- 主/子 Agent、实时/历史中的消息身份一致，不使用渲染数组下标。
- 不解析代码块里的路径，不把普通网页链接自动下载入库。
- 流式不完整链接不会启动错误资源请求；组件重绘不会上传或捕获文件。
- 同消息刷新/重连保持相同资源；同路径在新消息中使用不同捕获版本。
- 文件卡片能用于草稿、聊天和文件库，动作按场景区分。
- 预览失败时可读错误或下载降级，卡片尺寸变化不破坏本体阅读锚点。
- 后端文件请求失败不隐藏原生正文，不造成整个聊天白屏。

## 不以外观代替接入完成

最终应以独立构建的模块包和真实宿主接口完成上述流程。
静态 HTML、手工插 DOM、伪造上传成功或依赖宿主私有代码路径，不算模块接入完成。
前端符合接口也不代表后端捕获、持久化、权限和快照已经正确；后端验收须另行完成。
