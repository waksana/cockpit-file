# Roadmap

本文列出后续能力，不代表已经实现或需要在首版完成。

## 首版：聊天文件闭环

上传按钮、拖拽/粘贴、附件草稿、原生附件发送、助手 Markdown 文件捕获、
聊天文件卡片、预览和下载。前后端均按 best effort 识别流式中的文件引用。
仅处理模块启用后的新上传和新实时回复，旧历史不补捕获、不做兼容。
卡片每轮自动等待最多五秒，不无限 loading。

## 后续：全局文件库

- 汉堡菜单中的“文件库”入口。
- 文件总览、搜索和分页。
- 文件详情与集中预览。
- 从文件库选择已有文件加入聊天草稿。
- 文件管理与删除交互，连同保留政策一起设计。

首版仍需要内部文件 ID、托管原件和必要元数据，
但不因此提前开发总览页面、列表搜索 API 或通用文件管理 UI。

## 暂不实现的优化

首版不做跨文件的内容哈希去重、共享原件对象池、引用计数或自动垃圾回收。
同消息/同上传操作的幂等仍是首版正确性要求，不属于这里延期的内容去重。
是否在后续加入内容去重，根据真实重复率和存储成本决定，不预先承诺。

服务器项目目录编辑、移动和删除不属于当前已确认范围。
